# Як тестувалися моди

[English](TESTING.md) · [Усі моди](README.uk.md)

Усе нижче взято зі справжніх журналів: `log.txt` програми, `vrserver.txt` і
`basestation_wireless.txt` SteamVR, `coredumpctl`, `Player.log` Room Setup. Для серпневих
тестів на Windows джерело — описи самих комітів. Позначки:
- **наживо**: перевірено на справжньому обладнанні;
- **збирання**: лише компіляція / перевірка типів / застосування патча;
- **ще ні**: не перевірялося.

Серпневі коміти тестувалися ще й на ПК з Windows з тими самими станціями, зокрема
одночасно Windows і Linux на одній парі станцій. Версії Windows в описах комітів немає,
тому тут вона не вказана.

## Усі моди: перевірки збирання (26.09.2026)

- `go vet` для **linux** і **windows** (GOOS=windows) у кожній гілці й в `all-mods`; `tsc
  --noEmit` у кожній гілці зі змінами фронтенду.
- Кожен `mods/<назва>/<назва>.patch` застосовано через `git am` на свою основу, і код
  збігся з гілкою (10/10).
- `all-mods` = злиття всіх модів. Його код збігається з вашою робочою версією
  (`snapshot/2026-09-26`), крім запланованих змін для переносності (помічники play-area в
  `tools/`, `.gitignore`) і пізнішого фіксу спроб у play-area. `wails build -tags
  webkit2_41` проходить.

## По модах

### ble-connection — наживо (Windows + Linux, 03–06.08.2026), збирання (26.09)
- Дві ОС: Windows і Linux на тих самих двох станціях, потім Windows вимкнено. Linux-збірка
  написала `Giving up connecting … after 6 attempts` замість вічних спроб, а звичайні
  підключення на обох ОС проходили одразу.
- Гонка: одне підключення на станцію. Станція, що раніше перебирала шість невдалих спроб,
  підключилась з першої.
- Сканування «забутої» станції: тестовий скрипт підтвердив ланцюжок «not found» →
  8-секундне сканування бачить її (rssi −36) → підключення, 6 сервісів. У програмі станція,
  що раніше вичерпувала всі спроби, підключилась з першої.
- Журнали 26.09: у кожній сесії всі 3 станції підключилися з першого проходу (19:08,
  19:09, 22:01).

### power-state — наживо (Linux, 26.09.2026)
- **Баг відтворено (18:54):** LHB-624077D2 підтвердила дві команди «прокинутись» і
  лишилась темною; LHB-C27FF789 впала з `In Progress`, а перепідключення загубило команду.
  Інтерфейс показував усі три зеленими. SteamVR бачив лише LHB-83D4ADEA.
- **Причину підтверджено (19:04):** той самий `0x01`, надісланий вручну (`busctl …
  WriteValue`), за кілька секунд розбудив LHB-624077D2 (`vrserver.txt`: «finished adding
  tracked device … LHB-624077D2»); LHB-C27FF789 так само о 19:05.
- **Нова збірка (19:08–19:09):** станції «лише на запис» отримували повтори через
  +2/+5/+10/+15 с. `Not connected` на LHB-83D4ADEA → 3 повтори → перепідключення →
  **команду застосовано знову** → `confirmed (state 1)`.
- **Після прошивки (22:01):** усі 3 станції повідомляють стан. Пробудження підтверджено на
  кожній (`Power state 1 confirmed … (state 9)`) за 2–3 с, SteamVR бачить усі три.
- **Сон (22:05):** `Power state 0 confirmed` на всіх 3 за 2 с.
- **ще ні (і вже ніяк):** шлях «станція лише на запис» наживо не перевірити, бо тут уже
  немає станцій з радіо 2.2.

### play-area — наживо (частково), збирання
- **Бекенд (go-тест, SteamVR вимкнений):**
  - `GetRoomStatus` знаходить обидва помічники;
  - `ListZones` читає наявну зону «Кімната» (4.0 × 2.2 м, авто);
  - ID всесвіту зчитуються точно (`json.Number`);
  - помилки без SteamVR зрозумілі;
  - цикл «перейменувати/авто» лишає `zones.json` незмінним за змістом, і старий `vr-zones
    list` досі його читає.
- **Інтерфейс:** розмітку сторінки перевірено через `wails dev` у браузері. Виклики Go там
  недоступні, тому дані перевірялися тестом бекенду.
- **Жива сесія 22:01:**
  - спостерігач стартував разом із програмою, авто-зону застосовано `(спроба 5)` після
    4 × «wrong universe?». **Звідси фікс спроб** (до 2 хв). Сам фікс наживо **ще ні**;
  - кнопка калібрування двічі запустила майстер (22:02:19, 22:02:52) з активним шаром
    (`Player.log`: `[mipclamp] vkCreateImage extent/mips->max: 50 32 7 6`), падінь не було;
  - падіння о 22:02:05 (SIGTRAP в `Addr2ComputeSurfaceInfo`) — це кнопка Room Setup
    всередині SteamVR: у стеку є шар envextensions від SteamVR і немає `mipclamp`. Це
    задокументований невиправлений шлях.
- **Помічники:** `tools/vrchap-io` зібрано з джерел у репозиторії (з завантаженням
  `openvr.h` v2.15.6), `check` повертає код 3 без SteamVR. `tools/room-setup-fix` збирається gcc.
- **Перезастосування після `CALIBRATED base` прибрано 27.09.2026.** У сесії 27.09 воно
  спрацьовувало через 3–5 с після того, як контролер заново ловив станцію, і щоразу SteamVR
  писав «Standing origin changed», тобто скидав простір, який навмисно підняли
  (05:11:34, 05:32:56, 05:33:16, 05:34:54, 06:00:34). Коли простір ніхто не
  рухав, SteamVR писав «did not change» (05:12:36, 05:12:48), тобто воно нічого не виправляло.
